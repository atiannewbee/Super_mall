# Flyway 迁移 Review 说明

Flyway 会对已执行迁移保存校验和，因此 V1～V5 不再直接补写注释，避免仅因文档变化导致应用启动校验失败。下面记录各版本的设计目的，后续结构调整必须新增迁移版本。

- **V1**：创建消费者账号、地址、分类、品牌、商品、SKU、购物车、收藏、库存、订单、支付、物流和售后基础结构。表按外键依赖顺序创建。
- **V2**：写入与消费者前端一致的演示分类、品牌、商品、图片、SKU 和初始库存。固定主键只用于保持演示引用稳定。
- **V3**：为订单增加用户范围内的幂等键。空值兼容旧客户端，非空值由唯一索引阻止重复下单。
- **V4**：增加支付有效期、最后主动查询时间与异步通知记录。`channel + notification_id` 唯一约束用于防止重复通知再次推进状态。
- **V5**：增加商家、员工角色、仓库、履约操作人与审计日志，并把现有商品和订单归属到 `SUPER_MALL` 自营商户。初始密码由运行环境注入，不进入迁移。

新增迁移时应在文件头说明目的、数据回填策略、关键约束和回滚/兼容风险；迁移一旦在共享环境执行，禁止原地修改。
