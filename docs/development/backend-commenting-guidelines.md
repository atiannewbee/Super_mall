# 后端中文注释规范

本项目的注释目标是帮助人类开发者与 AI 快速恢复业务上下文，同时避免让注释重复代码或随实现变化而失真。

## 注释层次

1. **包级注释（package-info.java）**：说明模块职责、允许的依赖方向和安全边界。
2. **类级注释**：说明该类负责什么、不负责什么，以及它与相邻模块如何协作。
3. **方法级注释**：用于公共业务入口，重点描述事务边界、幂等性、权限和重要前置条件。
4. **行内注释**：只解释代码本身看不出的原因，例如固定锁顺序、条件更新防超卖、支付验签后的二次校验。
5. **迁移注释**：说明迁移目的、关键约束和数据归属。已执行的 Flyway 迁移禁止原地修改。

## 编写原则

- 优先解释“为什么”和“不变量”，不把 Java 或 SQL 逐行翻译成中文。
- 注释必须与代码一起更新；状态机、锁顺序、权限或金额规则改变时，同一提交内同步修改注释。
- 不在注释中记录密码、密钥、Token、真实手机号等敏感信息。
- `TODO` 必须包含明确问题和处理条件，不能用作长期需求清单。
- 对外错误码、数据库状态值和角色名保留源码中的英文常量，中文解释业务含义。

## Review 重点

- 所有消费者数据查询是否带 `user_id`，所有商家数据查询是否带 `merchant_id`。
- 订单、库存、支付和售后状态变化是否位于同一事务，并写入对应历史或审计记录。
- 库存是否使用条件更新检查受影响行数，避免先查后改导致超卖。
- 支付通知是否依次完成签名、应用身份、金额、交易号和幂等校验。
- Controller 是否只处理 HTTP 适配，业务规则是否保留在 Service。
