# 后端安全审查（2026-07-22）

## 审查结论

当前消费者端 MVP 未发现阻止本地联调的高危问题。认证、对象归属、SQL 参数化、金额可信边界、库存并发和错误信息隐藏已落实并有集成测试覆盖。真实生产上线仍需要完成下方“上线前外部措施”。

## 已落实

- BCrypt 密码哈希；数据库和 API 不保存或返回明文密码。
- HS256 JWT 强制至少 32 字节密钥，并校验签发者、受众、有效期和用户当前状态。
- 只有目录、登录、注册和最小健康检查公开；个人资源均需要 JWT。
- 地址、收藏、购物车、订单和售后查询/修改都同时带 `user_id` 条件，跨用户访问返回 404。
- Controller 只接收受校验 DTO；错误响应不泄露栈、SQL、数据库约束或内部异常。
- 所有用户输入 SQL 都使用命名参数；唯一动态排序来自固定白名单。
- 客户端提交的商品价格、订单金额和退款金额均被忽略，由数据库快照与服务器规则计算。
- 下单、取消、支付、超时和售后数量变更使用事务与条件更新，数据库 CHECK 约束作为第二层防线。
- 订单创建支持用户级幂等键；沙箱支付明确命名且生产默认关闭。
- CORS 仅允许配置的前端来源；CSRF 在无 Cookie、纯 Bearer Token 模式下关闭。
- Actuator 只暴露 `health` 与 `info`，健康详情不公开。

## 已接受的 MVP 限制

- JWT 没有刷新令牌，过期后重新登录；这是当前两小时访问令牌的简化选择。
- 订单列表为有上限分页，并逐单装配明细；数据规模增加后应改为批量装配或订单摘要投影。
- 登录失败次数未在单机内存中限流，避免多实例行为不一致；限流应在统一网关实施。

## 上线前外部措施

1. 域名全站 HTTPS，并由反向代理设置 HSTS、请求体上限、连接超时和安全日志脱敏。
2. 在网关对登录、注册、支付和售后接口配置按 IP/账号的速率限制与异常告警。
3. 使用密钥管理系统注入 `DB_PASSWORD` 与高熵 `JWT_SECRET`，不要将 `.env.properties` 上传服务器仓库。
4. 接入真实支付时必须校验支付方签名、金额、币种和事件幂等性；不能复用沙箱端点。
5. 物流和运营 Agent 写接口必须使用独立服务身份与最小权限，不得使用普通用户令牌。
6. 上线前执行依赖漏洞扫描、数据库备份恢复演练和并发压测。
