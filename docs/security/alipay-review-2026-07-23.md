# 支付宝支付安全审查（2026-07-23）

## 范围

- 支付单创建、支付宝页面跳转、主动查询、异步通知与交易关闭
- 订单、支付单、库存之间的状态转换与并发边界
- Vue 结算页、渠道返回页和支付状态轮询
- 密钥配置、访问控制、输入校验与依赖边界

## 审查结论

未发现尚未处理的 Critical 或 High 级问题。支付成功只能由服务端验签通知或主动查询触发，前端无法提交金额或直接改变支付状态。

## 已落实控制

1. 支付宝通知使用官方 SDK 执行 RSA2 验签，同时校验 AppID、可选 SellerID、支付单号、交易号和订单金额。
2. `payment_notifications` 对渠道与通知 ID 建立唯一约束；重复通知不会重复扣减库存。
3. 用户支付记录查询同时校验 JWT 与支付单所属用户；其他用户统一得到 404。
4. 支付跳转页只接受高熵支付单号，不读取前端金额、商品标题或任意 HTML。
5. 私钥和支付宝公钥只从环境变量或 Git 忽略的 `.env.properties` 读取，代码、响应和日志不输出密钥。
6. 支付确认在数据库事务内锁定订单与支付记录，通过条件更新将锁定库存一次性转为已售库存。
7. 回调、支付重试、取消和超时采用一致的“订单后支付单”锁顺序，降低死锁风险。
8. 取消或超时订单会先查询并关闭支付宝交易；在事务内再次确认不存在新的 PENDING 支付后才释放库存。
9. 金额篡改、伪造签名、重复通知、越权查询和安全关闭均有自动化测试。

## 上线前仍需完成

### Medium

1. 在 Nginx/WAF 对 `/api/payments/alipay/notify` 配置合理的请求体大小、连接超时和速率限制。签名校验保护数据完整性，但不能单独阻止资源耗尽攻击。
2. 在生产反向代理统一启用 HTTPS、HSTS、`X-Content-Type-Options`、`Referrer-Policy` 和适合前端资源域名的 CSP。

### Low

1. 官方 `alipay-sdk-java` 当前版本仍带入若干较旧的传递依赖。当前锁定官方发布版本 `4.40.918.ALL`；CI 应持续运行软件成分分析并跟随支付宝官方兼容版本升级，不应单独盲目覆盖传递依赖。
2. 退款接口必须等运营端角色与售后审核流完成后再开放。消费者接口不能直接调用 `alipay.trade.refund`。
3. 正式运营后应增加日对账单任务和异常支付人工处理队列。
