# SUPER MALL 后端设计

## 范围

本次交付实现当前 Vue3 消费者商城需要的后端能力：认证、个人资料、地址、分类、品牌、商品列表与搜索、商品详情、收藏、购物车、订单、库存、支付沙箱、物流查询和售后申请。Python AI 客服、运营 Agent、数据中台、真实支付渠道和运营后台不在本次范围，但通过应用服务和稳定 REST API 保留接入边界。

## 架构

项目继续采用 Spring Boot 4.1 模块化单体和单个 MySQL 数据库。Java 包按业务能力分为 `common`、`security`、`catalog`、`account`、`cart`、`order`、`aftersale`。商品目录是读多写少的组合查询，使用参数化 JDBC 投影；用户聚合沿用 JPA；购物车、订单、库存、支付和售后使用显式 SQL 事务，以便准确表达条件更新、金额计算和状态历史。

```text
Vue3 / Agent
      |
REST + Bearer JWT
      |
Controller -> Application Service -> Repository/Query
      |                                  |
      +---------- Spring Transaction ----+
                         |
                  MySQL + Flyway
```

## API 边界

- 公开：注册、登录、分类、品牌、商品列表、搜索和商品详情。
- 登录用户：个人资料、地址、收藏、购物车、订单、支付沙箱、物流和售后。
- 所有用户资源查询都同时使用资源编号和当前用户 ID，防止越权读取。
- API 返回 DTO，禁止直接序列化 Entity、密码哈希、软删除字段和内部版本号。
- JSON 错误使用统一结构：`code`、`message`、`details`、`timestamp`、`path`。

## 核心业务规则

1. 下单时忽略前端金额，重新读取 SKU 价格、状态和实时库存。
2. 创建订单、条件锁定库存、写库存流水、写状态历史和清理购物车在同一事务完成。
3. 待支付订单取消时释放锁定库存；支付成功时把锁定库存转为已售库存。
4. 支付状态变更保持幂等；生产环境必须关闭本地支付沙箱。
5. 订单保存商品、SKU、价格和地址快照。
6. 售后只能操作当前用户的可售后订单项，数量和退款金额由后端计算。

## 安全

- 密码使用 Spring Security BCrypt 自适应哈希。
- Access Token 使用 HS256 JWT，校验签名、发行方、受众和过期时间；密钥仅来自环境变量或被忽略的本地配置。
- API 无状态，不创建服务器会话；CORS 只允许配置的前端来源。
- 所有 SQL 使用参数绑定；动态排序只从服务端白名单选择。
- 认证失败和业务异常不返回堆栈、SQL 或敏感信息。
- 真实部署使用 HTTPS、低权限数据库用户，并关闭支付沙箱。

## 非功能目标

- 商品普通查询目标 p95 小于 500ms；默认分页最多 20 条，请求最大 100 条。
- 单机部署面向 MVP，Hikari 最大连接数 10；后续按观测结果引入缓存和读副本。
- Flyway 是唯一 DDL 来源，Hibernate 仅做映射校验。
- 订单、库存、支付与售后变更必须保留历史或流水。

## 测试策略

- DTO、金额和状态转换使用单元测试。
- 数据库约束、商品投影、库存事务和所有权校验使用集成测试。
- 关键消费者流程使用 MockMvc：注册/登录、浏览商品、地址、购物车、下单、支付、订单查询和售后。
- 最终执行全量测试、打包、依赖树检查、凭据扫描和 REST 冒烟验证。

## 失败模式

| 失败 | 处理 |
|---|---|
| 库存不足或并发抢购 | 条件更新影响行数为 0，整个订单事务回滚 |
| 重复支付 | 已支付状态直接返回原结果，不重复扣库存 |
| 越权访问订单/地址 | 查询包含当前用户 ID，外部统一返回 404 |
| 支付渠道不可用 | 支付单保持 PENDING，订单保持待支付 |
| 数据库不可用 | 请求失败且不产生部分写入；由健康检查和部署监控告警 |
